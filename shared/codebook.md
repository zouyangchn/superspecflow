# Codebook — 团队编码规范基准

> 本文件是团队级编码规范的**权威基准**。当 superspecflow skill 为项目生成 `openspec/specs/coding-conventions.md` 时，必须以此为基线，再叠加从项目代码中提取的特有约定。
>
> **约束力说明**：【强制】必须遵守；【推荐】建议遵守，特殊情况可灵活处理；【参考】视场景选择性采纳。

---

## 一、基准文件结构指引

子项目的 `coding-conventions.md` 应至少包含以下章节，按此结构组织：

```markdown
# coding-conventions.md — <项目名>

## 命名规范
## 代码格式
## OOP / 面向对象规约
## 常量与魔法值
## 集合处理
## 并发处理
## 控制语句
## 注释规约
## 异常处理
## 日志规约
## 安全编码
## 单元测试
## 项目特有约定   ← 此节由项目分析生成，基准文件中不覆盖
```

## 二、命名规范

### 2.1 通用命名

**2.1.1** 【强制】命名不能以下划线或美元符号开始或结束。

**2.1.2** 【强制】禁止拼音与英文混合命名，更不允许直接使用中文。纯拼音也要避免。

**2.1.3** 【强制】类名使用 `UpperCamelCase`，但 `DO / BO / DTO / VO / AO / PO / UID` 等缩写例外。

**2.1.4** 【强制】方法名、参数名、成员变量、局部变量统一使用 `lowerCamelCase`。

**2.1.5** 【强制】常量命名全部大写，单词间用下划线隔开。

**2.1.6** 【强制】抽象类以 `Abstract` 或 `Base` 开头；异常类以 `Exception` 结尾；测试类以 `Test` 结尾。

**2.1.7** 【强制】POJO 类中布尔类型变量不要加 `is` 前缀，防止序列化错误。

**2.1.8** 【强制】包名统一小写，点分隔符间有且仅有一个自然语义的英语单词，使用单数形式。

**2.1.9** 【强制】杜绝完全不规范的缩写。

**2.1.10** 【推荐】使用设计模式时，命名中体现模式名称（如 `OrderFactory`、`LoginProxy`）。

**2.1.11** 【推荐】类型名词放在词尾（如 `startTime`、`workQueue`、`nameList`）。

### 2.2 各层命名规约

| 层级 | 操作 | 前缀 |
|------|------|------|
| Service/DAO | 获取单个对象 | `get` |
| Service/DAO | 获取多个对象 | `list`，复数结尾如 `listObjects` |
| Service/DAO | 获取统计值 | `count` |
| Service/DAO | 插入 | `save` / `insert` |
| Service/DAO | 删除 | `remove` / `delete` |
| Service/DAO | 修改 | `update` |

### 2.3 领域模型命名

| 类型 | 格式 | 说明 |
|------|------|------|
| 数据对象 | `xxxDO` | xxx 为数据表名 |
| 数据传输对象 | `xxxDTO` | xxx 为业务领域名称 |
| 展示对象 | `xxxVO` | xxx 一般为网页名称 |
| 查询对象 | `xxxQuery` | 超过 2 个参数的查询封装，禁止使用 Map |

> 禁止命名成 `xxxPOJO`。

## 三、常量定义

**3.1** 【强制】不允许魔法值直接出现在代码中，必须预定义为常量。

**3.2** 【强制】`long` / `Long` 赋值时数值后使用大写 `L`，不用小写 `l`。

**3.3** 【推荐】按功能归类常量，不要用一个类维护所有常量。

**3.4** 【推荐】值仅在固定范围内变化时使用 `enum` 定义。

---

## 四、代码格式

**4.1** 【强制】大括号规则：空块 `{}`；非空块左括号前不换行后换行，右括号前换行。

**4.2** 【强制】`if/for/while/switch/do` 与括号间必须加空格。运算符两侧必须加空格。

**4.3** 【强制】采用 4 个空格缩进，禁止 tab 字符。

**4.4** 【强制】单行不超过 120 字符，超出换行时第二行缩进 4 个空格。

**4.5** 【强制】注释双斜线与内容之间有且仅有一个空格。

**4.6** 【强制】方法参数逗号后必须加空格。

**4.7** 【强制】文件编码 UTF-8，换行符 Unix 格式。

**4.8** 【推荐】单个方法总行数不超过 80 行。

**4.9** 【推荐】不同逻辑之间插入一个空行分隔，不要用多个空行。

---

## 五、OOP 规约

**5.1** 【强制】覆写方法必须加 `@Override` 注解。

**5.2** 【强制】外部依赖的接口不允许修改方法签名，过时接口加 `@Deprecated` 并说明替代方案。

**5.3** 【强制】`equals` 比较使用常量或确定非 null 的对象调用，或使用 `Objects.equals()`。

**5.4** 【强制】所有整型包装类值的比较使用 `equals`，不用 `==`。

**5.5** 【强制】货币金额以最小单位整型存储。浮点数等值判断使用 `BigDecimal` 或指定误差范围。

**5.6** 【强制】禁止 `BigDecimal(double)` 构造，使用 `BigDecimal(String)` 或 `BigDecimal.valueOf()`。

**5.7** 【强制】POJO 类属性必须使用包装数据类型；RPC 方法返回值和参数必须使用包装数据类型。

**5.8** 【强制】DO/DTO/VO 类不要设定属性默认值。

**5.9** 【强制】构造方法禁止加入业务逻辑。

**5.10** 【强制】POJO 类必须写 `toString`。

**5.11** 【推荐】类内方法顺序：公有/保护 > 私有 > getter/setter。

**5.12** 【推荐】类成员与方法访问控制从严：工具类无 public 构造方法；仅本类使用的用 private。

---

## 六、日期时间

**6.1** 【强制】年份用小写 `y`（`yyyy`），月份大写 `M`，分钟小写 `m`，24 小时制大写 `H`。

**6.2** 【强制】获取当前毫秒数用 `System.currentTimeMillis()`，不用 `new Date().getTime()`。

**6.3** 【强制】禁止使用 `java.sql.Date`、`java.sql.Time`、`java.sql.Timestamp`。

**6.4** 【强制】不要写死一年为 365 天，使用 `LocalDate.now().lengthOfYear()`。

---

## 七、集合处理

**7.1** 【强制】重写 `equals` 必须重写 `hashCode`。

**7.2** 【强制】判空用 `isEmpty()`，不用 `size() == 0`。

**7.3** 【强制】`Collectors.toMap()` 必须指定 `mergeFunction`，注意 value 为 null 时 NPE。

**7.4** 【强制】`ArrayList.subList()` 不可强转 `ArrayList`。

**7.5** 【强制】不要在 `foreach` 中 `remove/add`，使用 `Iterator`。

**7.6** 【强制】`addAll()` 时检查输入集合 NPE。

**7.7** 【强制】集合转数组用 `toArray(new T[0])`。

**7.8** 【推荐】集合初始化时指定大小。`HashMap` 初始容量 = (元素个数 / 0.75) + 1。

**7.9** 【推荐】遍历 Map 用 `entrySet`，JDK8 用 `Map.forEach`。

---

## 八、并发处理

**8.1** 【强制】创建线程或线程池时必须指定有意义的线程名称。

**8.2** 【强制】线程资源必须通过线程池提供，禁止自行创建线程。

**8.3** 【强制】线程池用 `ThreadPoolExecutor` 创建，禁止 `Executors`。

**8.4** 【强制】`SimpleDateFormat` 线程不安全，JDK8 推荐 `DateTimeFormatter`。

**8.5** 【强制】必须回收自定义 `ThreadLocal`，在 `try-finally` 中 `remove()`。

**8.6** 【强制】能用无锁就不用锁；能锁区块就不锁方法体；能用对象锁就不用类锁。

**8.7** 【强制】对多个资源加锁时保持一致的加锁顺序，防止死锁。

**8.8** 【强制】阻塞获取锁时，`lock()` 必须在 `try` 代码块之外。

**8.9** 【强制】并发修改同一记录时必须加锁。乐观锁（冲突率 < 20%）重试不少于 3 次。

**8.10** 【推荐】资金相关使用悲观锁，遵循"一锁二判三更新四释放"原则。

---

## 九、控制语句

**9.1** 【强制】`switch` 中每个 `case` 必须 `break/return`，必须有 `default`。

**9.2** 【强制】`switch` 中 `String` 外部参数必须先做 null 判断。

**9.3** 【强制】`if/else/for/while/do` 中必须使用大括号。

**9.4** 【强制】三目运算符注意自动拆箱导致的 NPE。

**9.5** 【推荐】if-else 超过 3 层时用卫语句、策略模式、状态模式替代。

**9.6** 【推荐】不要在条件判断中执行复杂语句，赋值给有意义的布尔变量。

**9.7** 【推荐】接口入参保护，批量操作需限制最大批量大小。

---

## 十、注释规约

**10.1** 【强制】类/属性/方法注释使用 Javadoc（`/** */`），不用 `//`。

**10.2** 【强制】所有抽象方法必须有 Javadoc，说明做什么、返回值、参数、异常。

**10.3** 【强制】所有类必须添加 `@author` 和 `@date`。

**10.4** 【强制】所有枚举字段必须有注释。

**10.5** 【推荐】代码修改时注释同步更新。

**10.6** 【推荐】无用代码直接删除，不要注释保留。需要查看历史时从代码仓库获取。

**10.7** 【参考】特殊标记格式：`TODO(人, 时间, 预计处理时间)` 和 `FIXME(人, 时间, 预计处理时间)`。

---

## 十一、异常处理

**11.1** 【强制】可预检查的 RuntimeException 不应通过 catch 处理（如 NPE、IndexOutOfBoundsException）。

**11.2** 【强制】异常不要用来做流程控制。

**11.3** 【强制】catch 时区分稳定代码和非稳定代码，尽量区分异常类型。

**11.4** 【强制】捕获异常必须处理或上抛，不能吞掉。最外层必须转化为用户可理解的内容。

**11.5** 【强制】事务中 catch 后需回滚时，手动回滚事务。

**11.6** 【强制】`finally` 中关闭资源/流。JDK7+ 使用 `try-with-resources`。

**11.7** 【强制】不要在 `finally` 中 `return`。

**11.8** 【强制】调用 RPC/二方包/动态类方法时，用 `Throwable` 拦截。

**11.9** 【推荐】使用有业务含义的自定义异常（如 `DAOException / ServiceException`），不直接抛 `RuntimeException`。

---

## 十二、日志规约

**12.1** 【强制】使用 SLF4J 日志门面，不直接使用 Log4j/Logback API。

**12.2** 【强制】日志文件至少保存 15 天。

**12.3** 【强制】日志拼接使用占位符 `logger.debug("id: {}, name: {}", id, name)`。

**12.4** 【强制】`trace/debug/info` 级别输出前必须做级别判断。

**12.5** 【强制】禁止 `System.out` 和 `e.printStackTrace()`。

**12.6** 【强制】异常日志包含案发现场信息和异常堆栈。

**12.7** 【强制】禁止直接用 JSON 工具将对象转 String 打日志。

**12.8** 【推荐】生产环境禁止 `debug`；`error` 只记系统逻辑错误和重要异常。

---

## 十三、安全编码

**13.1** 【强制】用户个人页面/功能必须进行权限校验，防止水平越权。

**13.2** 【强制】敏感数据展示必须脱敏（手机号 `137****0969`）。

**13.3** 【强制】SQL 参数必须使用参数绑定，禁止字符串拼接 SQL。

**13.4** 【强制】所有用户传入参数必须做有效性验证。

**13.5** 【强制】禁止向 HTML 输出未过滤/未转义的用户数据。

**13.6** 【强制】表单/AJAX 提交必须执行 CSRF 验证。

**13.7** 【强制】URL 外部重定向必须白名单过滤。

**13.8** 【强制】短信/邮件/支付等平台资源必须有防重放机制。

---

## 十四、单元测试

**14.1** 【强制】遵循 AIR 原则：Automatic、Independent、Repeatable。

**14.2** 【强制】使用 `assert` 验证，禁止 `System.out` 人肉验证。

**14.3** 【强制】测试用例独立，不互相依赖。

**14.4** 【强制】测试代码放在 `src/test/java`。

**14.5** 【推荐】语句覆盖率 70%；核心模块 100%。

**14.6** 【推荐】遵循 BCDE 原则：Border、Correct、Design、Error。

---

## 十五、工具类与公共组件

**15.1** 【强制】HTTP 请求、线程池等必须统一使用工具类方法，禁止在业务代码中直接写。

**15.2** 【强制】禁止增加与业务无关的测试代码。

**15.3** 【强制】正则表达式使用预编译，定义为类静态常量。

**15.4** 【强制】属性 copy 不用 Apache BeanUtils，用 Spring BeanUtils 或 Cglib BeanCopier。

---

## 附录：生码自查清单

```
- [ ] 命名规范符合
- [ ] 无魔法值
- [ ] 分层清晰（Controller 无业务逻辑，Service 无 SQL 拼接）
- [ ] NPE 防护到位
- [ ] 集合初始化指定大小，判空用 isEmpty()
- [ ] 线程池用 ThreadPoolExecutor，ThreadLocal 有回收
- [ ] 日志用 SLF4J 占位符，debug/info 有级别判断
- [ ] 异常处理正确（不吞异常、finally 关资源）
- [ ] 安全性（SQL 绑定、入参校验、脱敏）
- [ ] 核心模块有单元测试
```
